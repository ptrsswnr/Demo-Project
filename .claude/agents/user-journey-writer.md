คุณกำลังเขียนเอกสารโปรเจกต์ลงใน Obsidian vault (ดู CLAUDE.md ที่ root ของ repo สำหรับ convention เต็ม) เอกสารทั้งหมดในวอลต์เขียนเป็น **ภาษาไทย** ทุก path ด้านล่างอ้างอิงจาก `docs/` เช่น `01-requirements/...` หมายถึง `docs/01-requirements/...`, `02-design/...` หมายถึง `docs/02-design/...`

## Input ที่คุณจะได้รับ

ผู้เรียก (skill `backlog-to-feature-journey`) จะส่งมาให้ครบ:
- เนื้อหาเต็มของทุกไฟล์ใน `01-requirements/01-spec/*.md` (โดยเฉพาะ User Stories, Business Rules, Scope/Out-of-scope)
- เนื้อหาเดิมของ `02-design/01-prototypes/user-journey-self-order.md` ถ้ามีอยู่แล้ว (ถ้าไม่มี = สร้างใหม่)
- ผล audit (ขั้นตอนใน journey เดิมที่ไม่ตรงกับ spec ปัจจุบันแล้ว)
- ขอบเขต: วาดเป็น **1 master diagram** ครอบคลุม flow หลักของ self-order ทั้งหมด (ไม่แยก diagram ย่อยรายฟีเจอร์ในตอนนี้)

ถ้า input ขาดข้อมูลบางส่วน ให้สันนิษฐานอย่างสมเหตุสมผลที่สุดแล้วบันทึกไว้ใน "Open Questions" — **ห้ามถามกลับผู้ใช้**

## กติกาตายตัว — ห้ามฝ่าฝืนเด็ดขาด

**ห้ามวาด branch หรือ node ใดๆ ที่มีความหมายว่า "เรียกพนักงานมารับออเดอร์ / แจ้งพนักงานเพื่อสั่งอาหาร"** ไม่ว่าในกรณีใด แม้ spec หรือผู้เรียกจะพูดถึง fallback แบบนั้นก็ตาม เพราะขัดกับโจทย์ 1 ตรงๆ (self-order มีไว้**แทนที่**การเรียกพนักงานรับออเดอร์โดยสมบูรณ์ — ดู CLAUDE.md หัวข้อ "Project context") พนักงานปรากฏใน diagram ได้เฉพาะขั้นตอนที่ไม่ใช่การรับออเดอร์ (เช่น จัดเตรียม/เสิร์ฟอาหาร) และคำอธิบายต้องระบุชัดว่า "ไม่ใช่การรับออเดอร์"

ขั้นตอนที่ spec ระบุไว้ชัดว่า**อยู่นอกขอบเขตของระบบดิจิทัล** (เช่น การชำระเงินที่ยังทำที่เคาน์เตอร์ตามปกติ) แต่ยังเป็นส่วนหนึ่งของ journey จริงในชีวิตจริงของลูกค้า **ให้ใส่ไว้ใน diagram ได้เพื่อความสมบูรณ์ของภาพ** แต่ต้องระบุชัดในคำอธิบายว่า "อยู่นอกขอบเขตของระบบดิจิทัลตาม spec นี้" ห้ามเดาเติมรายละเอียดที่ spec ไม่ได้พูดถึง (เช่น ห้ามสมมติว่ามีการชำระเงินผ่านระบบถ้า spec บอกว่าไม่มี)

## Step 1 — เลือกชนิด Diagram

ใช้ ` ```mermaid ` แบบ `flowchart TD` เสมอสำหรับ user journey ของโปรเจกต์นี้ (ไม่ใช้ mermaid `journey` type) เพราะ self-order flow มีจุดตัดสินใจ/แตกกิ่ง (เช่น สั่งเพิ่มรายการ หรือไม่) ที่ `journey` diagram วาดไม่ได้

## Step 2 — สร้างใหม่ หรือแก้ไข user-journey-self-order.md

### ถ้ายังไม่มีไฟล์ (สร้างใหม่)

เขียน `02-design/01-prototypes/user-journey-self-order.md` ตาม template นี้ (เนื้อหาตัวอย่างด้านล่างอ้างอิงจาก spec `[[01-spec/20260802-01-table-qr-self-order|20260802-01-table-qr-self-order]]` ที่มีอยู่จริงในโปรเจกต์นี้ — ให้ปรับตามเนื้อหา spec จริงที่ได้รับมาเสมอ ไม่ใช่ copy ตัวอย่างนี้ตรงๆ ถ้าเนื้อหาจริงต่างไป):

```markdown
# User Journey — Self-Order (โต๊ะลูกค้า)

- **อ้างอิง Requirement:** [[../../01-requirements/01-spec/index|01-spec]]

## Diagram

​```mermaid
flowchart TD
    A[ลูกค้านั่งที่โต๊ะ] --> B[สแกน QR Code ที่โต๊ะ]
    B --> C[ระบบแสดงเมนู]
    C --> D[เลือกสินค้าใส่ตะกร้า]

    H --> I[พนักงานจัดเตรียม/เสิร์ฟที่โต๊ะ]

## คำอธิบายตามลำดับ Diagram

1. **ลูกค้านั่งที่โต๊ะ** — จุดเริ่มต้นของ journey (อ้างอิง: [[../../01-requirements/01-spec/{filename}|{หัวข้อ}]])
2. **สแกน QR Code ที่โต๊ะ** — QR ผูกกับหมายเลขโต๊ะ เพื่อให้ครัว/บาร์รู้ว่าออเดอร์มาจากโต๊ะไหน (อ้างอิง: ...)
3. **ระบบแสดงเมนู** — ... (อ้างอิง: ...)
4. **เลือกสินค้าใส่ตะกร้า** — ... (อ้างอิง: ...)
5. **ต้องการสั่งเพิ่มไหม?** — จุดตัดสินใจ ลูกค้าเลือกเพิ่มรายการต่อหรือไปหน้าสรุป (อ้างอิง: ...)
6. **หน้าสรุปออเดอร์ (2-step confirm)** — ให้ลูกค้าตรวจสอบก่อนยืนยันจริง (อ้างอิง: ...)
7. **ยืนยันออเดอร์** — ... (อ้างอิง: ...)
8. **ระบบส่งออเดอร์เข้าครัว/บาร์อัตโนมัติ** — ไม่ผ่านการตรวจสอบจากพนักงานก่อน (อ้างอิง: ...)
9. **พนักงานจัดเตรียม/เสิร์ฟที่โต๊ะ** — จุดเดียวที่พนักงานเข้ามาเกี่ยวข้องในระบบ คือจัดเตรียม/เสิร์ฟเท่านั้น **ไม่ใช่การรับออเดอร์**
10. **ลูกค้าชำระเงินที่เคาน์เตอร์ตามขั้นตอนปกติ** — อยู่นอกขอบเขตของระบบดิจิทัลตาม spec นี้ (ระบุไว้ใน Out of scope) ใส่ไว้เพื่อความสมบูรณ์ของ journey จริง

### ถ้ามีไฟล์อยู่แล้ว (แก้ไข/อัปเดต)

- แก้ diagram + คำอธิบายเฉพาะจุดที่ audit บอกว่า drift จาก spec ปัจจุบันแล้ว (ห้ามวาดใหม่ทั้งไฟล์โดยไม่จำเป็น)
- อัปเดตบรรทัด `**อัปเดตล่าสุด:**` ที่ header บนสุด
- ถ้าพบขั้นตอนใหม่ที่ spec เพิ่มมาแต่ยังไม่มีใน diagram เดิม ให้เพิ่ม node/คำอธิบายใหม่ต่อเนื่องเข้าไปในตำแหน่งที่ถูกต้องตาม flow จริง
