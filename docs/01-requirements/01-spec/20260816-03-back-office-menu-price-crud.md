# Back-office จัดการเมนู/ราคา (CRUD พื้นฐาน) สำหรับพนักงาน

- **วันที่สร้าง:** 2026-08-16
- **อ้างอิงโจทย์:** โจทย์ 1 — ผู้ประกอบการร้านกาแฟต้องการให้ลูกค้าสั่ง Order เองจากที่โต๊ะ
- **สถานะ:** Draft
- **เอกสารที่เกี่ยวข้อง:** [[01-spec/20260802-01-table-qr-self-order|20260802-01-table-qr-self-order]] (สเปกเดิมที่ระบุ Out of scope ว่าการจัดการเมนู/สต๊อกฝั่งพนักงานต้องทำ requirement แยก), [[01-spec/20260815-01-kitchen-notification-order-handling|20260815-01-kitchen-notification-order-handling]] (มี flag เปิด/ปิดขายเมนูแบบง่ายอยู่แล้ว และระบุ Out of scope ว่าระบบจัดการเมนู/สต๊อกแบบเต็มรูปแบบต้องทำเป็น requirement แยกในอนาคต — เอกสารนี้คือ requirement แยกนั้น แต่ไม่รวม stock count)

## ความต้องการ (Requirement)
ปัจจุบันเมนูที่ลูกค้าเห็นในระบบ self-order (ตาม [[01-spec/20260802-01-table-qr-self-order|20260802-01-table-qr-self-order]]) และปุ่มเปิด/ปิดขายชั่วคราวรายวัน (ตาม [[01-spec/20260815-01-kitchen-notification-order-handling|20260815-01-kitchen-notification-order-handling]]) ยังไม่มีที่มาว่าเมนู/ราคาเหล่านั้นถูกสร้าง/แก้ไขจากที่ไหน requirement นี้จึงกำหนดหน้า back-office ให้พนักงาน/เจ้าของร้านสามารถจัดการรายการเมนู, ราคา, และหมวดหมู่เมนูได้เอง โดยเป็น CRUD พื้นฐาน (เพิ่ม/แก้ไข/ลบ) **ไม่รวมการนับจำนวนสต๊อก/วัตถุดิบ** — เรื่องสต๊อกยังคงใช้กลไก flag เปิด-ปิดขายแบบง่ายที่มีอยู่แล้วใน 20260815-01

## User Stories
- ในฐานะเจ้าของร้าน/พนักงาน ฉันต้องการเพิ่มเมนูใหม่พร้อมชื่อ, ราคา, และหมวดหมู่ เพื่อให้เมนูนั้นแสดงในระบบ self-order ของลูกค้า
- ในฐานะเจ้าของร้าน/พนักงาน ฉันต้องการแก้ไขชื่อ/ราคา/หมวดหมู่ของเมนูที่มีอยู่แล้ว เพื่ออัปเดตข้อมูลให้ถูกต้องเมื่อราคาเปลี่ยนหรือต้องการปรับปรุงเมนู
- ในฐานะเจ้าของร้าน/พนักงาน ฉันต้องการลบเมนูที่เลิกขายถาวรออกจากระบบ เพื่อไม่ให้ค้างอยู่ในเมนูของลูกค้าอีกต่อไป (แยกจากปุ่มปิดขายชั่วคราวใน 20260815-01 ซึ่งใช้กับเมนูที่ยังขายอยู่แต่ของหมดชั่วคราว)
- ในฐานะเจ้าของร้าน/พนักงาน ฉันต้องการจัดกลุ่มเมนูเป็นหมวดหมู่ (เช่น กาแฟ, ชา, ของหวาน) เพื่อให้ลูกค้าเรียกดูเมนูได้ง่ายขึ้น

## Business Rules / เงื่อนไข
- ระบบต้องมีหน้า back-office ที่จำกัดสิทธิ์เข้าถึงเฉพาะเจ้าของร้าน/พนักงานที่ได้รับอนุญาตเท่านั้น (แนวทางเดียวกับการจำกัดสิทธิ์เข้าถึง order log ใน [[01-spec/20260802-01-table-qr-self-order|20260802-01-table-qr-self-order]])
- CRUD เมนูประกอบด้วยอย่างน้อย: ชื่อเมนู, ราคา, หมวดหมู่ — ไม่รวมรูปภาพ/คำอธิบายเมนู/ตัวเลือกปรับแต่ง (เช่น ความหวาน) ในเวอร์ชันแรก เว้นแต่จะระบุเพิ่มภายหลัง
- การลบเมนู (permanent) เป็นคนละกลไกกับปุ่มเปิด/ปิดขายชั่วคราวที่มีอยู่แล้วใน [[01-spec/20260815-01-kitchen-notification-order-handling|20260815-01-kitchen-notification-order-handling]] (flag on/off) — การลบคือเอาเมนูออกจากระบบถาวร ส่วน flag คือซ่อนชั่วคราวเมื่อของหมด
- **ไม่รวมการนับจำนวนสต๊อก/วัตถุดิบในเอกสารนี้** — ผู้ใช้ยืนยันชัดเจนว่าต้องการแค่ CRUD เมนู/ราคาพื้นฐาน สต๊อกยังคงพึ่งพา flag เปิด-ปิดขายแบบ manual ตามเดิม
- เมนูที่แก้ไข/เพิ่มใหม่ผ่าน back-office ต้องแสดงผลในหน้าเมนูของลูกค้า (self-order) ทันทีหรือเมื่อลูกค้ารีเฟรช/เปิดเมนูใหม่ (สอดคล้องกับ pattern การแสดงผล "หมดชั่วคราว" ใน 20260815-01)

## ขอบเขต (Scope)
**อยู่ในขอบเขต (In scope):**
- CRUD เมนู: เพิ่ม/แก้ไข/ลบ ชื่อ, ราคา, หมวดหมู่
- การจำกัดสิทธิ์เข้าถึงหน้า back-office เฉพาะเจ้าของร้าน/พนักงานที่ได้รับอนุญาต
- การแสดงผลเมนูที่อัปเดตแล้วในหน้า self-order ของลูกค้า

**ไม่อยู่ในขอบเขต (Out of scope):**
- การนับจำนวนสต๊อก/วัตถุดิบ (manual หรือ real-time) — ยังคงใช้ flag เปิด-ปิดขายแบบง่ายตามเดิมใน [[01-spec/20260815-01-kitchen-notification-order-handling|20260815-01-kitchen-notification-order-handling]] ถ้าต้องการ stock count จริงต้องทำเป็น requirement แยกในอนาคต
- รูปภาพเมนู, คำอธิบายเมนู, ตัวเลือกปรับแต่งเมนู (เช่น ความหวาน, ชนิดนม) — ไม่รวมในเวอร์ชันแรก (สอดคล้องกับ Open Question ของ [[01-spec/20260802-01-table-qr-self-order|20260802-01-table-qr-self-order]] ที่ระบุว่ายังไม่รองรับการปรับแต่งเมนู)
- การจัดการผู้ใช้/สิทธิ์แบบละเอียด (role-based permission หลายระดับ) — ใช้แนวทางง่ายๆ แบบเดียวกับ order log access control ก่อน ถ้าต้องการ role หลายระดับให้แยก requirement

## คำถามที่ยังไม่ชัดเจน (Open Questions)
- ยังไม่ระบุว่าจะรองรับรูปภาพเมนูหรือไม่ในเวอร์ชันถัดไป (สมมติฐาน: เวอร์ชันแรกยังไม่รองรับ)
- ยังไม่ระบุว่าการลบเมนูที่เคยมีอยู่ในประวัติออเดอร์เก่าจะกระทบ order log ที่เก็บไว้หรือไม่ (สมมติฐาน: order log เก็บชื่อรายการ ณ เวลาที่สั่งไว้แล้ว ไม่ผูกกับเมนูปัจจุบัน จึงไม่กระทบ)
