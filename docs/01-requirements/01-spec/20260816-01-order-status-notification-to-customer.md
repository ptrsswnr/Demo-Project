# การแจ้งเตือนสถานะออเดอร์กลับไปยังลูกค้า

- **วันที่สร้าง:** 2026-08-16
- **อ้างอิงโจทย์:** โจทย์ 1 — ผู้ประกอบการร้านกาแฟต้องการให้ลูกค้าสั่ง Order เองจากที่โต๊ะ
- **สถานะ:** Draft
- **เอกสารที่เกี่ยวข้อง:** [[01-spec/20260802-01-table-qr-self-order|20260802-01-table-qr-self-order]] (สเปกเดิมที่ระบุการแจ้งเตือนสถานะออเดอร์กลับไปยังลูกค้าเป็น out-of-scope และให้ทำเป็น requirement แยก), [[01-spec/20260815-01-kitchen-notification-order-handling|20260815-01-kitchen-notification-order-handling]] (นิยามสถานะออเดอร์ 3 สถานะฝั่งครัว/บาร์ ซึ่งเอกสารนี้นำมาแสดงผลฝั่งลูกค้า)

## ความต้องการ (Requirement)
ลูกค้าที่สั่งอาหาร/เครื่องดื่มเองผ่านการสแกน QR code ที่โต๊ะ (ตาม [[01-spec/20260802-01-table-qr-self-order|20260802-01-table-qr-self-order]]) และออเดอร์ถูกส่งเข้าครัว/บาร์แล้ว (ตาม [[01-spec/20260815-01-kitchen-notification-order-handling|20260815-01-kitchen-notification-order-handling]]) ปัจจุบันไม่มีทางรู้สถานะออเดอร์ของตัวเองเลยหลังจากยืนยันออเดอร์ไปแล้ว ทำให้ต้องเรียกพนักงานมาถามสถานะ ซึ่งขัดกับเจตนารมณ์ของโจทย์ 1 ที่ต้องการตัดขั้นตอนการเรียกพนักงานออกจาก flow หลัก

เอกสารนี้กำหนดให้ระบบแสดงสถานะออเดอร์แบบ real-time บนหน้าจอเว็บ/แอปที่ลูกค้าใช้อยู่แล้ว (หน้าเดียวกับที่ใช้สั่งอาหาร) โดยลูกค้าไม่ต้องกดรีเฟรชเอง และไม่ต้องขอ permission แจ้งเตือนแบบ push notification เพิ่มเติม (เพื่อลด friction) — mechanism ทางเทคนิคเบื้องหลัง (polling หรือ push ฝั่ง backend เช่น WebSocket/SSE) เป็นรายละเอียดที่ตัดสินใจในเฟส design ถัดไป ไม่ใช่ในเอกสาร requirement นี้

## User Stories
- ในฐานะลูกค้าที่เพิ่งยืนยันออเดอร์ไปแล้ว ฉันต้องการเห็นสถานะออเดอร์ของตัวเองอัปเดตแบบ real-time บนหน้าจอที่ใช้สั่งอาหาร เพื่อรู้ความคืบหน้าโดยไม่ต้องเรียกพนักงานมาถาม
- ในฐานะลูกค้า ฉันต้องการเห็นสถานะ "ส่งแล้ว (รอครัวรับทราบ)" ทันทีหลังยืนยันออเดอร์ เพื่อมั่นใจว่าออเดอร์เข้าระบบแล้วจริง
- ในฐานะลูกค้า ฉันต้องการเห็นสถานะเปลี่ยนเป็น "ครัวรับทราบแล้ว (กำลังทำ)" เมื่อครัว/บาร์กดรับทราบออเดอร์ เพื่อรู้ว่าเริ่มทำแล้ว และรู้ว่าออเดอร์ถูกล็อกแก้ไขเองไม่ได้อีกต่อไป (เชื่อมโยงกับกติกาการล็อกออเดอร์ใน [[01-spec/20260815-01-kitchen-notification-order-handling|20260815-01-kitchen-notification-order-handling]])
- ในฐานะลูกค้า ฉันต้องการเห็นสถานะเปลี่ยนเป็น "เสร็จ/เสิร์ฟแล้ว" เพื่อรู้ว่าออเดอร์เสร็จสมบูรณ์

## Business Rules / เงื่อนไข
- ต้องแสดงสถานะออเดอร์ครบทั้ง 3 สถานะที่นิยามไว้ใน [[01-spec/20260815-01-kitchen-notification-order-handling|20260815-01-kitchen-notification-order-handling]]: "ส่งแล้ว (รอครัวรับทราบ)" → "ครัวรับทราบแล้ว (กำลังทำ)" → "เสร็จ/เสิร์ฟแล้ว"
- การอัปเดตสถานะต้องเป็น real-time บนหน้าจอเว็บ/แอปที่ลูกค้าเปิดค้างไว้ (หน้าเดียวกับที่ใช้สั่งอาหาร/ดูเมนู) โดยลูกค้าไม่ต้องกดรีเฟรชเอง — กลไกทางเทคนิคเบื้องหลัง (polling interval, WebSocket, server-sent events ฯลฯ) เป็นเรื่องของ 02-design/02-technical ในเฟสถัดไป ไม่ใช่ขอบเขตของเอกสารนี้
- ไม่ใช้ push notification ผ่านมือถือ (ไม่ต้องขอ permission แจ้งเตือนจากลูกค้า) เพื่อลด friction ของ flow หลัก — ถ้าในอนาคตต้องการ push notification ให้แยกเป็น requirement ใหม่
- การแสดงสถานะนี้เป็น read-only ฝั่งลูกค้า ไม่กระทบกับกติกาการแก้ไข/ยกเลิกออเดอร์ที่นิยามไว้แล้วใน [[01-spec/20260815-01-kitchen-notification-order-handling|20260815-01-kitchen-notification-order-handling]] (ลูกค้ายังคงแก้ไข/ยกเลิกได้เฉพาะช่วง "ส่งแล้ว (รอครัวรับทราบ)" เท่านั้นตามเดิม)

## ขอบเขต (Scope)
**อยู่ในขอบเขต (In scope):**
- แสดงสถานะออเดอร์ 3 สถานะแบบ real-time บนหน้าจอลูกค้า (หน้าเดียวกับที่ใช้สั่งอาหาร)
- อัปเดตสถานะโดยอัตโนมัติไม่ต้องให้ลูกค้ากดรีเฟรช

**ไม่อยู่ในขอบเขต (Out of scope):**
- Push notification ผ่านมือถือ/แจ้งเตือนนอกหน้าเว็บ — ยกไปทำ requirement แยกในอนาคตถ้าต้องการ
- รายละเอียดทางเทคนิคของกลไก real-time (WebSocket vs polling vs SSE) — เป็นเรื่องของ 02-design/02-technical ในเฟสถัดไป
- การแจ้งเตือนช่องทางอื่นนอกเหนือจากหน้าจอที่ลูกค้าใช้สั่งอาหารอยู่แล้ว (เช่น SMS, LINE notify)

## คำถามที่ยังไม่ชัดเจน (Open Questions)
- กลไกทางเทคนิคเบื้องหลัง (push จาก backend เมื่อสถานะเปลี่ยน vs polling เป็นระยะ) ยังไม่ตัดสินใจ — ยกไปเฟส design
- ยังไม่ระบุว่าถ้าลูกค้าปิดหน้าเว็บ/แอปไปแล้วเปิดใหม่ (เช่น สแกน QR ซ้ำ) จะยังเห็นสถานะออเดอร์เดิมของโต๊ะได้หรือไม่ (สมมติฐาน: เห็นได้ เพราะสถานะผูกกับโต๊ะ ไม่ผูกกับ session อุปกรณ์ ตาม logic การรวมออเดอร์ของโต๊ะใน [[01-spec/20260815-01-kitchen-notification-order-handling|20260815-01-kitchen-notification-order-handling]])
