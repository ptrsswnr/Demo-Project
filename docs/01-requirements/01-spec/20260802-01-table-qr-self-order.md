# ลูกค้าสั่งอาหาร/เครื่องดื่มเองผ่านการสแกน QR code ที่โต๊ะ

- **วันที่สร้าง:** 2026-08-02
- **แก้ไขล่าสุด:** 2026-08-02
- **อ้างอิงโจทย์:** โจทย์ 1 — ผู้ประกอบการร้านกาแฟต้องการให้ลูกค้าสั่ง Order เองจากที่โต๊ะ
- **สถานะ:** Draft
- **เอกสารที่เกี่ยวข้อง:** ไม่มี

## ความต้องการ (Requirement)
ผู้ประกอบการร้านกาแฟต้องการระบบช่วยรับ Order จากลูกค้า โดยให้ลูกค้าสามารถสแกน QR code ที่ติดอยู่บนโต๊ะ เพื่อเปิดดูเมนูร้านกาแฟและสั่งอาหาร/เครื่องดื่มได้เองจากมือถือของตัวเอง โดยไม่ต้องเรียกพนักงานมารับออเดอร์ที่โต๊ะ เมื่อลูกค้ายืนยันออเดอร์แล้ว ระบบจะส่งออเดอร์เข้าครัว/บาร์ให้อัตโนมัติ

## User Stories
- ในฐานะลูกค้าที่นั่งอยู่ที่โต๊ะ ฉันต้องการสแกน QR code บนโต๊ะ เพื่อเปิดดูเมนูร้านกาแฟบนมือถือของตัวเอง
- ในฐานะลูกค้า ฉันต้องการเลือกรายการอาหาร/เครื่องดื่มจากเมนู แล้วเพิ่มลงตะกร้าออเดอร์ เพื่อสั่งได้เองโดยไม่ต้องเรียกพนักงาน
- ในฐานะลูกค้า ฉันต้องการเห็นหน้าสรุปออเดอร์ก่อนกดยืนยัน เพื่อตรวจสอบความถูกต้องก่อนส่งเข้าครัว
- ในฐานะลูกค้า เมื่อกดยืนยันออเดอร์แล้ว ฉันต้องการให้ระบบส่งออเดอร์เข้าครัว/บาร์โดยอัตโนมัติ โดยไม่ต้องรอพนักงานมา confirm ก่อน

## Business Rules / เงื่อนไข
- QR code แต่ละอันต้องผูกกับหมายเลขโต๊ะที่แน่นอน เพื่อให้ครัว/บาร์รู้ว่าออเดอร์นี้มาจากโต๊ะไหน
- ออเดอร์จะถูกส่งเข้าครัว/บาร์ทันทีหลังจากลูกค้ายืนยันซ้ำในหน้าสรุปออเดอร์ (2-step confirm) โดยไม่ผ่านการตรวจสอบจากพนักงานก่อน
- การชำระเงินไม่รวมอยู่ในขอบเขตของ requirement นี้ — ลูกค้ายังคงจ่ายเงินที่เคาน์เตอร์ตามขั้นตอนปกติของร้านหลังใช้บริการเสร็จ (ดูหัวข้อ scope)
- **การเก็บ log ออเดอร์และการปฏิบัติตาม PDPA:**
  - ระบบเก็บ order log เฉพาะข้อมูล: เลขโต๊ะ + เวลา + รายการอาหาร เท่านั้น เวอร์ชันแรกของระบบ **ไม่เก็บข้อมูลที่ระบุตัวตนลูกค้าได้เลย** (ไม่เก็บเบอร์โทร/ชื่อลูกค้า) จึงไม่ถือเป็นข้อมูลส่วนบุคคลตาม PDPA เพราะไม่สามารถระบุตัวตนบุคคลได้
  - เก็บ order log ไว้เป็นระยะเวลา 90 วัน นับจากวันที่เกิดออเดอร์ หลังจากนั้นต้องลบหรือ anonymize ข้อมูลทิ้ง
  - ต้องมีกระบวนการลบ/anonymize ข้อมูลอัตโนมัติเมื่อครบ 90 วัน (ไม่ใช่แค่ policy บนกระดาษ)
  - ต้องจำกัดสิทธิ์เข้าถึง order log ภายในร้าน ให้เข้าถึงได้เฉพาะเจ้าของร้าน/พนักงานที่ได้รับอนุญาตเท่านั้น
  - เนื่องจากเวอร์ชันนี้ไม่เก็บข้อมูลระบุตัวตน จึงยังไม่ต้องทำ privacy notice/consent flow เต็มรูปแบบ (ดูข้อสมมติฐานในหัวข้อ Open Questions)

## ขอบเขต (Scope)
**อยู่ในขอบเขต (In scope):**
- การสแกน QR เพื่อเปิดเมนู
- การเลือกรายการอาหาร/เครื่องดื่มและเพิ่มลงตะกร้า
- หน้าสรุปออเดอร์ก่อนยืนยัน (2-step confirmation)
- การส่งออเดอร์เข้าครัว/บาร์อัตโนมัติหลังยืนยัน
- นโยบายการเก็บรักษา (retention policy) ของ order log เป็นเวลา 90 วัน พร้อมกระบวนการลบ/anonymize อัตโนมัติเมื่อครบกำหนด
- การจำกัดสิทธิ์เข้าถึง order log ภายในร้านเฉพาะเจ้าของร้าน/พนักงานที่ได้รับอนุญาต

**ไม่อยู่ในขอบเขต (Out of scope):**
- ระบบชำระเงินออนไลน์/QR payment — ตัดสินใจแล้วว่าไม่รวมในเอกสารนี้ ยกไปทำ requirement แยกในอนาคต
- การจัดการเมนู/สต๊อกฝั่งพนักงาน (back office) — ต้องทำ requirement แยกต่างหาก
- การแจ้งเตือนสถานะออเดอร์กลับไปยังลูกค้า (เช่น "อาหารกำลังทำ" / "เสิร์ฟแล้ว") — ต้องทำ requirement แยกต่างหาก
- Privacy notice/consent flow แบบเต็มรูปแบบสำหรับข้อมูลที่ระบุตัวตนได้ (เช่น เบอร์โทร/ชื่อ) — ไม่รวมในเอกสารนี้ เพราะเวอร์ชันนี้ไม่เก็บข้อมูลประเภทดังกล่าว

## คำถามที่ยังไม่ชัดเจน (Open Questions)
- ยังไม่ระบุว่าเมนูจะรองรับหลายภาษาหรือไม่ (สมมติฐาน: เริ่มต้นรองรับภาษาไทยอย่างเดียวก่อน)
- ยังไม่ระบุว่าจะรองรับการปรับแต่งรายการอาหาร (เช่น ความหวาน, ชนิดนม) หรือไม่ (สมมติฐาน: เวอร์ชันแรกยังไม่รองรับ ใช้ค่ามาตรฐานของแต่ละเมนู)
- ถ้าในอนาคตมีฟีเจอร์ที่เก็บเบอร์โทร/ชื่อ (เช่น ระบบสมาชิกหรือแจ้งเตือนสถานะออเดอร์กลับไปยังลูกค้า) ต้องกลับมาทำ privacy notice + consent flow ใหม่ให้สอดคล้องกับ PDPA เนื่องจากข้อมูลนั้นจะถือเป็นข้อมูลส่วนบุคคล
