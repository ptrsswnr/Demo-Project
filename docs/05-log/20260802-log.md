# Log — 2026-08-02

## สร้างเอกสาร requirement แรกของโปรเจกต์: ลูกค้าสั่งอาหารเองผ่าน QR code ที่โต๊ะ
- เอกสาร requirement: [[01-spec/20260802-01-table-qr-self-order|ลูกค้าสั่งอาหาร/เครื่องดื่มเองผ่านการสแกน QR code ที่โต๊ะ]] (สร้างใหม่)
- อัปเดต backlog: เพิ่มแถวลำดับ 1 ความสำคัญสูง สถานะ Draft
- รายละเอียด: บันทึก requirement ตามโจทย์ 1 ครอบคลุมการสแกน QR เปิดเมนู เลือกรายการ สั่งผ่านตะกร้า ยืนยันแบบ 2-step แล้วส่งเข้าครัว/บาร์อัตโนมัติ โดยไม่รวมการชำระเงิน, back office, และการแจ้งเตือนสถานะออเดอร์ ซึ่งเป็นขอบเขตของ requirement ในอนาคต

## เพิ่มเงื่อนไข PDPA/data retention สำหรับ order log ในเอกสาร QR self-order
- เอกสาร requirement: [[01-spec/20260802-01-table-qr-self-order|ลูกค้าสั่งอาหาร/เครื่องดื่มเองผ่านการสแกน QR code ที่โต๊ะ]] (แก้ไข)
- อัปเดต backlog: แก้ไขแถวลำดับ 1 — ปรับหัวข้อให้สะท้อนขอบเขตที่ขยายเพิ่ม (data retention/PDPA), อัปเดตล่าสุดเป็น 2026-08-02 (ความสำคัญของแถวยังคงเป็น "สูง" เหมือนเดิม เนื่องจาก core flow การสั่งอาหารยังเป็นตัวกำหนด priority ของทั้งเอกสาร — ส่วน PDPA/log retention ที่เพิ่มมาเป็น priority "กลาง" เฉพาะส่วนย่อยนั้น ระบุกำกับไว้ในคอลัมน์หัวข้อแทน)
- รายละเอียด: เพิ่ม business rule เรื่องการเก็บ order log (เลขโต๊ะ + เวลา + รายการอาหาร เท่านั้น ไม่เก็บข้อมูลระบุตัวตน) เก็บ 90 วันแล้วต้องลบ/anonymize อัตโนมัติ พร้อมจำกัดสิทธิ์เข้าถึงเฉพาะเจ้าของร้าน/พนักงานที่ได้รับอนุญาต เพิ่ม in-scope (retention policy + จำกัดสิทธิ์เข้าถึง) และ out-of-scope (privacy notice/consent แบบเต็มรูปแบบ) และเพิ่ม open question ว่าถ้าในอนาคตเก็บเบอร์โทร/ชื่อ ต้องกลับมาทำ privacy notice + consent ใหม่ตาม PDPA
- แก้ไขเพิ่มเติมหลังตรวจพบ: agent ที่เขียนเอกสารรอบแรกปรับ priority ทั้งแถวจาก "สูง" เป็น "กลาง" อย่างไม่ถูกต้อง (เอา priority ของส่วนเสริมไปทับของทั้งเอกสาร) แก้กลับเป็น "สูง" แล้ว
